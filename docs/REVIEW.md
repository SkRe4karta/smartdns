# Проверка реализации беты

Это отчёт проверки автором реализации, а не Approve второго аккаунта. Финальные эксплуатационные проверки ещё не закончены.

Исправленные замечания с регрессионными проверками:

- Ответ DNS из кэша допуска мог скрывать отказ агента. Теперь проверяется свежая готовность агента/узла, изменение поколения сбрасывает применимость кэша.
- Привязка Telegram могла завершиться после отзыва сеанса. Сеанс проверяется до обмена кода и повторно внутри транзакции привязки.
- Более точное импортированное правило могло перекрыть ручное direct-исключение. Ручные правила проверяются первыми.
- Сбой применения каталога оставлял новый каталог в базе. API/CLI используют общий механизм блокировки и восстановления таблиц каталога; аккаунты не откатываются.
- Query-параметр периода статистики не принимался из браузера. Значение преобразуется в integer и допускает только сутки/неделю; проверено браузером.
- Восстановление аккаунта оставляло действующим старый пароль. Сброс теперь отменяет пароль, Telegram и сеансы до нового первоначального входа.
- Старые DNS-профили переживали смену общего ключа. Ротация удаляет legacy-допуски.
- Rate-limit записи имели несовместимые единицы времени при очистке. Добавлено явное время истечения.

Отдельно проверяются изоляция аккаунтов, инвайты при гонке, неизвестные DNS-ключи, spoofed X-Real-IP, malformed DNS, несколько DoT frames, TLS-клиенты без mTLS-сертификата, старое поколение узла, срок допуска, failover и отказ без подходящего выхода.

До выпуска остаются обязательными: реальный Telegram, интеграция с живым HAProxy/AGH, испытания kill/hang, длительная нагрузка, восстановление и откат, клиентские приложения и подтверждение SHA развёрнутого артефакта. Они не подменяются тестовыми адаптерами.

Дополнительно исправлена очистка DNS-истории при отсутствии трафика: обслуживание запускается и при пустой очереди, а API сразу скрывает события старше суток. Регрессионный тест проверяет срок и физическую очистку без новых запросов.

Проверка в CI также выявила зависимость первого обслуживания от uptime машины. Первая очистка теперь выполняется без ожидания минуты, а основной агент и выходной узел явно требуют состоявшуюся синхронизацию перед готовностью, даже в первые секунды после загрузки ОС. Добавлены проверки начального закрытого состояния.
